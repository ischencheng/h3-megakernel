# B200 FastH3 V2: one prompt per checkpoint

The Starter workspace did allocate a B200. The earlier queued request's system message did not establish a plan restriction. A short B200 probe succeeded, followed by both benchmarks. The full H3 function ran after reducing its requested host memory from 128 GiB to 64 GiB; this change may have helped scheduling, but the precise cause of the earlier queue is unconfirmed.

Both jobs used the sole prompt in `baseline/prompts.json` (basketball shot during school recess), seed 1101, 1344×768, 124 frames, 24 fps, nine sigma-grid points/eight DiT forwards, VSA sparsity 0.8 with tile size 64, BF16 VSA attention (`FASTVIDEO_H3_VSA_FP4=0`), and no offload. Each job called `generator.generate` exactly once; Modal retries were zero. These are cold first requests, not steady-state benchmarks.
